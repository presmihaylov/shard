Ask a server which lifecycle verbs it supports before you call one. A verb the provider lacks fails with an error, so code that pauses or forks can check first and take another path. On a Sysbox server:

<Tabs syncKey="lang">
	<TabItem label="CLI">
		```sh
		shard capabilities
		```

		```text
		CAPABILITY   SUPPORTED
		create       true
		start        true
		stop         true
		remove       true
		pause        false
		resume       false
		fork         false
		snapshot     true
		port         true
		swap         false
		```
	</TabItem>
	<TabItem label="TypeScript">
		```ts
		import { Shard } from "useshards";

		const shard = new Shard();
		try {
		  const caps = await shard.capabilities();
		  console.log(caps.pause, caps.fork); // false false
		} finally {
		  shard.close();
		}
		```
	</TabItem>
	<TabItem label="Python">
		```python
		from useshards import Shard

		with Shard() as shard:
		    caps = shard.capabilities()
		    print(caps.pause, caps.fork)  # False False
		```
	</TabItem>
</Tabs>

The SDK examples connect to the server that `SHARD_REMOTE` names, with the API key in `SHARD_API_KEY`.

The answer lists all nine verbs and swap, each `true` or `false`. It comes from the provider of the daemon, so it is the same for every sandbox on that server. Token scopes and sandbox states never change it.

## The verbs of each provider

One daemon runs one provider for every sandbox on its host. Every provider supports the same six of the nine verbs. Pause, resume and fork are optional:

| Verb | gVisor | Sysbox | runc | vz | Firecracker |
| --- | --- | --- | --- | --- | --- |
| `create`, `start`, `stop`, `remove`, `snapshot`, `port` | yes | yes | yes | yes | yes |
| `pause` | yes | no | no | Apple silicon with macOS 14 or later | yes |
| `resume` | yes | no | no | Apple silicon with macOS 14 or later | yes |
| `fork` | yes | no | no | Apple silicon with macOS 14 or later | yes |

- **`snapshot`:** `shard snapshot create`, which copies the files of a stopped sandbox.
- **`fork`:** copies a sandbox while it runs.
- **`port`:** `shard port add`, which forwards a host port into a sandbox.
- **`swap`:** whether `--swap` can give a sandbox a swap file: yes on vz and Firecracker, no on the rest.
- **Not listed:** every provider also supports `exec`, `logs` and `inspect`, which the answer leaves out.

For what each provider is and how they differ, see [Providers and capabilities](/docs/concepts/providers/).

## The API

`GET /v0/capabilities` answers the same ten fields:

```sh
curl --unix-socket /var/lib/shard/shard.sock http://localhost/v0/capabilities
```

```json
{
  "create": true,
  "start": true,
  "stop": true,
  "remove": true,
  "pause": false,
  "resume": false,
  "fork": false,
  "snapshot": true,
  "port": true,
  "swap": false
}
```

Through `shard serve`, any valid token can read it, whatever its scopes. `shard capabilities --format json` prints the same object.

## A verb the provider lacks

shard refuses the verb. It never falls back to a weaker verb, such as a stop in place of a pause. The refusal comes before the daemon changes anything, so the sandbox keeps its state:

<Tabs syncKey="lang">
	<TabItem label="CLI">
		```sh
		shard pause quiet-heron-3f0a
		# shard: provider sysbox does not support pause on this host; use a server that supports pause
		```
	</TabItem>
	<TabItem label="TypeScript">
		```ts
		import { Shard, UnsupportedError } from "useshards";

		const shard = new Shard();
		try {
		  // Sysbox has no pause, so this throws UnsupportedError.
		  const sandbox = await shard.get("quiet-heron-3f0a");
		  await sandbox.pause();
		} catch (err) {
		  if (!(err instanceof UnsupportedError)) throw err;
		  console.log(err.status, err.code); // 409 unsupported
		} finally {
		  shard.close();
		}
		```
	</TabItem>
	<TabItem label="Python">
		```python
		from useshards import Shard, UnsupportedError

		with Shard() as shard:
		    sandbox = shard.get("quiet-heron-3f0a")

		    # Sysbox has no pause, so this raises UnsupportedError.
		    try:
		        sandbox.pause()
		    except UnsupportedError as err:
		        print(err.status, err.code)  # 409 unsupported
		```
	</TabItem>
</Tabs>

The API answers 409 with the code `unsupported`:

```json
{"error":{"code":"unsupported","message":"provider sysbox does not support pause on this host; use a server that supports pause"}}
```

The message names the provider and the verb. [Errors and exit codes](/docs/reference/errors/) lists every code.

## The provider of a host

`shard daemon status` names the provider of the running daemon, and `shard daemon --provider <name>` picks one. For how a daemon started without the flag picks one from its root and the host, see [How a host picks its provider](/docs/concepts/providers/#how-a-host-picks-its-provider).
