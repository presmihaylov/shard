The shard command line and the SDKs talk to the daemon over this API. This request creates a sandbox named `web`, over the daemon's socket:

```sh
curl --unix-socket /var/lib/shard/shard.sock -X POST -H 'Content-Type: application/json' -d '{"name":"web","image":"alpine:3.20","command":["sleep","600"],"resources":{"memory_mib":512}}' http://localhost/v0/sandboxes
```

The daemon answers `201` with the [Sandbox](/docs/reference/api/sandboxes/#sandbox) as JSON. Each page under REST API covers one group of routes, and the [Routes](#routes) tables below list them all.

## Reach the API

On the host, the daemon listens on a unix socket, `/var/lib/shard/shard.sock` by default, and never on TCP. The socket needs no token, and a request on it can do anything. If the host has a `shard` group, its members can open the socket without root.

From another host, you reach the API through `shard serve`. It listens on `127.0.0.1:2376` by default, checks each request's token, then passes the request to the socket. Put a proxy that terminates TLS in front of it. Mint a token on the host, then send it in the `Authorization` header:

```sh
export SHARD_API_KEY=$(shard tokens mint --name ci --scopes sandbox:read,exec | jq -r .token)
curl -H "Authorization: Bearer $SHARD_API_KEY" http://127.0.0.1:2376/v0/sandboxes
```

A client on another host sends the same header to the proxy.

## Scopes

Each route names the scope a token needs to reach it. A token with no scopes, or with `*`, reaches every route in this reference. A route marked "any token" accepts every valid token. `GET /v0/scopes` lists the scopes, and `shard tokens mint --scopes` takes them.

`shard serve` refuses some requests before they reach the daemon:

| Status | Code | When |
| --- | --- | --- |
| 401 | `unauthorized` | The token is missing, does not verify, has expired, or was revoked. |
| 403 | `forbidden` | The token's scopes do not cover the route, or the route is unknown or local. |

A create that names a secret also needs `secret:*`, and one that names a policy also needs `policy:*`. A fork of a sandbox that holds a secret or a policy needs the same scope. Without it, the daemon answers `403` with `forbidden`.

The local routes answer only on the socket, and this reference leaves them out. They are `GET /v0/daemon`, which `shard daemon status` reads, and the four `images` routes, which `shard pull` and `shard image` use.

## Lists

A list returns every row unless the request passes `limit`. With `limit`, it returns at most that many rows, and `next` names the last row when more remain. Pass `next` as `cursor` to read the page after it. On the last page, `next` is `null`.

```sh
curl --unix-socket /var/lib/shard/shard.sock 'http://localhost/v0/sandboxes?limit=20'
curl --unix-socket /var/lib/shard/shard.sock 'http://localhost/v0/sandboxes?limit=20&cursor=<next>'
```

## Errors

A refused request gets a `4xx` or `5xx` status and the [Error](#error) body. A `HEAD` request gets the status alone. Match on the `code`, never on the `message`. [Errors and exit codes](/docs/reference/errors/#error-codes) lists every code and when the daemon returns it.

## WebSockets

The routes that follow a stream, such as an exec attach or a `logs` follow, upgrade to a WebSocket and answer `101`. Their sections list the messages. An exec, an app attach and a `logs` follow send binary messages, and each message starts with a stream byte. An `egress-log` follow sends one text message per decision.

| `code` | string | yes | What a program matches on: invalid\_request, body\_too\_large, not\_found, sandbox\_not\_running, sandbox\_not\_stopped, sandbox\_not\_paused, sandbox\_live, sandbox\_failed, no\_checkpoint, unsupported, in\_use, name\_taken, exec\_exited, exec\_running, exec\_limit, no\_app, app\_ended, unauthorized, forbidden, timeout, command\_not\_started or internal.
