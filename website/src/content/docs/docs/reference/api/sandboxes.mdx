This creates a sandbox named `web`, then stops it. A stopped sandbox keeps its files, and a start runs it again:

```sh
curl --unix-socket /var/lib/shard/shard.sock -X POST -H 'Content-Type: application/json' -d '{"name":"web","image":"alpine:3.20","command":["sleep","600"],"resources":{"memory_mib":512}}' 'http://localhost/v0/sandboxes?wait=true'
curl --unix-socket /var/lib/shard/shard.sock -X POST http://localhost/v0/sandboxes/web/stop
curl --unix-socket /var/lib/shard/shard.sock -X POST http://localhost/v0/sandboxes/web/start
```

Every `{id}` in a path takes a sandbox's id or name. A create on vz or Firecracker needs `resources.memory_mib`, because the memory of a VM is real memory on the host.

## Create a sandbox

`POST /v0/sandboxes` · scope `sandbox:write`

A create that names secrets also needs the secret:\* scope, and one that names a policy needs policy:\*; without it the answer is 403 forbidden.

**Parameters**

| Name | In | Type | Required | Description |
| --- | --- | --- | --- | --- |
| `wait` | query | boolean | no | Answer once the sandbox leaves pending; with Accept: application/x-ndjson the pull streams first. |

**Request body**

[CreateRequest](#createrequest) as `application/json`, required.

**Responses**

| Status | Body | Description |
| --- | --- | --- |
| 201 | [Sandbox](#sandbox) as `application/json`, or [CreateLine](#createline) as `application/x-ndjson` | The sandbox, or with wait and Accept: application/x-ndjson one CreateLine per pull event and then the sandbox. An error after the first line ends the stream with a CreateLine whose error is set, and no sandbox. |

## Read or follow the output of a sandbox

`GET /v0/sandboxes/{id}/logs` · scope `sandbox:read`

**Parameters**

| Name | In | Type | Required | Description |
| --- | --- | --- | --- | --- |
| `id` | path | string | yes | The sandbox id or name. |
| `follow` | query | boolean | no | Keep the stream open until the sandbox stops or is removed; a WebSocket upgrade requires follow=true. |

**Responses**

| Status | Body | Description |
| --- | --- | --- |
| 101 | WebSocket | A WebSocket follow with follow=true. Each binary message leads with its stream byte: 1 the output, 3 an EndMessage naming why the follow ended, 5 a FailureMessage. |
| 200 | string as `text/plain` | The entrypoint's output as it was written; with follow the body streams until the sandbox stops or is removed. |

**WebSocket messages**

| Stream byte | Payload |
| --- | --- |
| 3 | [EndMessage](#endmessage) |
| 5 | [FailureMessage](#failuremessage) |

## Read or follow the egress decisions of a sandbox

`GET /v0/sandboxes/{id}/egress-log` · scope `sandbox:read`

**Parameters**

| Name | In | Type | Required | Description |
| --- | --- | --- | --- | --- |
| `id` | path | string | yes | The sandbox id or name. |
| `follow` | query | boolean | no | Keep the stream open until the sandbox stops or is removed; a WebSocket upgrade requires follow=true. |

**Responses**

| Status | Body | Description |
| --- | --- | --- |
| 101 | WebSocket | A WebSocket follow with follow=true: one egress decision per text message, until the sandbox stops, fails or is removed. |
| 200 | array of [EgressDecision](#egressdecision) as `application/json`, or [EgressDecision](#egressdecision) as `application/x-ndjson` | The egress decisions, oldest first; with follow one decision per line until the sandbox stops, fails or is removed. |

**Response headers**

| Header | Status | Type | Description |
| --- | --- | --- | --- |
| `Shard-Egress-Cut` | 200 | integer | The older decisions the read left out; absent when it left out none. |
