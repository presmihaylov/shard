Each number on this page is how long one `shard` command took, from the start of the CLI to its exit, against a daemon on the same machine. To time a command the same way on your host:

```sh
shard create --name demo --memory 512MiB alpine:3.20
time shard exec demo true
shard remove --force demo
```

On Linux, run them in a root shell, so `sudo` does not add to the time.

## Common commands

The median time in milliseconds over 10 runs of each command:

| Command | `firecracker` | `gvisor` | `sysbox` | `runc` | `vz` |
| --- | ---: | ---: | ---: | ---: | ---: |
| `shard create --name demo --memory 512MiB alpine:3.20` | 665 | 266 | 347 | 261 | 445 |
| `shard exec demo true` | 9 | 35 | 47 | 76 | 27 |
| `shard pause demo` | 543 | 191 | not supported | not supported | 571 |
| `shard resume demo` | 265 | 195 | not supported | not supported | 336 |
| `shard fork --name demo-fork demo` | 378 | 244 | not supported | not supported | 779 |
| `shard stop demo` | 120 | 50 | 52 | 58 | 138 |
| `shard start demo` | 708 | 261 | 728 | 381 | 381 |
| `shard remove --force demo` | 212 | 99 | 512 | 210 | 160 |
| `shard run --name demo-run --memory 512MiB alpine:3.20 true` | 897 | 305 | 449 | 305 | 756 |

The Linux providers ran on one host and `vz` ran on a Mac, so compare the Linux columns with each other and not with `vz`. Each section below names its machine.

## How the numbers were measured

- One script ran every command 10 times on each provider, after one untimed warm-up round.
- Each time is the wall-clock time of one `shard` process, including CLI start-up. The CLI spoke to the daemon over its local socket. A client that connects to a remote server through `shard serve` also waits for the network.
- The tables give the median and the 90th percentile by nearest rank: 9 of the 10 runs took that long or less.
- The script pulled `alpine:3.20` before the first run, and created every sandbox with `--memory 512MiB`.
- The sandbox commands ran on one sandbox, in the order of the tables. `create` starts it. `pause`, `resume`, `fork` and `policy logs` find it running. `secret grant`, `secret ungrant`, `policy attach`, `policy detach` and `snapshot create` find it stopped. `start` runs it again, and `remove --force` removes it while it runs. `fork` and `create --snapshot` each made a second sandbox, which the script then removed outside the timing.
- `shard pull alpine:3.20` finds the image already cached. `shard pull busybox:1.36` pulls an image that the previous round removed, so its time depends on the network.
- A command that the provider does not support shows "not supported".
- The script did not time `shard daemon` and `shard serve`, which run until you stop them, the interactive `shard setup`, or `logs -f`, `policy logs -f` and `exec -it`, which follow or attach.
