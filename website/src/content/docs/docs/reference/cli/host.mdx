## shard capabilities

Show sandbox lifecycle capabilities supported by the connected shard server.

```text
shard capabilities [OPTIONS]
```

**Examples**

```sh
shard capabilities
shard capabilities --format json
```

**Options**

| Option | Description | Default |
| --- | --- | --- |
| `--format <format>` | output format: json or table | `table` |

Lists all eight verbs, each true or false for the server's provider. Token scopes and sandbox states never change the answer.

## shard daemon

Start the daemon or show its status.

```text
shard daemon [OPTIONS]
shard daemon status [OPTIONS]
```

**Examples**

```sh
shard daemon
shard daemon --provider gvisor
```

**Commands**

| Command | Description |
| --- | --- |
| [`shard daemon status`](#shard-daemon-status) | show daemon status |

**Options**

| Option | Description | Default |
| --- | --- | --- |
| `--provider <name>` | sandbox provider: gvisor, sysbox, runc, vz or firecracker |  |
| `--timeout <duration>` | image download timeout | `30m` |
| `--insecure-registry <host>` | allow HTTP for a registry; repeatable |  |
| `--log <path>` | daemon log file (macOS only) |  |

The daemon manages local sandboxes and stays active until stopped. An existing data directory must use its original provider. Use `shard info` to see the default provider for this host.

Runs only on the daemon host and refuses `--remote`, `SHARD_REMOTE` and a saved connection.

## shard serve

Start an HTTP API server with token authentication.

```text
shard serve [OPTIONS]
```

**Example**

```sh
shard serve
```

**Options**

| Option | Description | Default |
| --- | --- | --- |
| `--listen <address>` | listen address | `127.0.0.1:2376` |
| `--signing-key-file <path>` | token signing key | `<root>/auth/signing-key` |

The local daemon must be active. Use `shard tokens mint` to create API keys.

Use an HTTPS proxy or tunnel for public access. HTTP is suitable for local access or an encrypted VPN.

The default signing key is created automatically on first use. A custom signing key file must already exist.

Runs only on the daemon host and refuses `--remote`, `SHARD_REMOTE` and a saved connection.

## shard setup

Set up shard on this machine or connect to a remote server.

Run without options to start the interactive wizard. For automated setup, specify the choices below.

```text
shard setup [OPTIONS]
```

**Examples**

```sh
shard setup
shard setup --local --provider gvisor --start-at-boot=true -y
shard setup --remote https://shard.example.com --save -y
```

**Options**

| Option | Description |
| --- | --- |
| `--local` | set up this machine to run sandboxes |
| `--remote <url>` | connect to a remote shard server |
| `--provider <name>` | firecracker, gvisor, sysbox, runc or vz |
| `--start-at-boot <true\|false>` | start the daemon at boot |
| `--save` | save the remote connection |
| `-y, --yes` | apply changes without confirmation |

**Remote authentication**

Set `SHARD_API_KEY`. Do not pass the key as a command argument.

**Exit codes**

- `0`: setup finished, or there was nothing to do
- `1`: a check or a step failed, an option was refused, or the confirmation was declined
- `130`: Ctrl+C left setup; the steps done so far stay in place

## shard tokens

Create, list and revoke API keys.

```text
shard tokens COMMAND [OPTIONS] [ARGS...]
```

**Commands**

| Command | Description |
| --- | --- |
| [`shard tokens mint`](#shard-tokens-mint) | create an API key |
| [`shard tokens list`](#shard-tokens-list) | list API keys and their status |
| [`shard tokens revoke`](#shard-tokens-revoke) | revoke an API key |
| [`shard tokens scopes`](#shard-tokens-scopes) | list available token scopes |

mint, list and revoke run only on the daemon host and refuse `--remote`. scopes follows `--remote` and `SHARD_REMOTE`.

### shard tokens mint

Create an API key.

```text
shard tokens mint [OPTIONS]
```

**Examples**

```sh
shard tokens mint --name build-agent --duration 24h
shard tokens mint --name reader --duration 24h --scopes sandbox:read
```

**Options**

| Option | Description | Default |
| --- | --- | --- |
| `--name <name>` | token owner or purpose; required |  |
| `--duration <duration>` | token lifetime; default no expiry |  |
| `--scopes <list>` | permissions, separated by commas; default all permissions |  |
| `--signing-key-file <path>` | token signing key | `<root>/auth/signing-key` |
| `--format <format>` | output format: json or table | `json` |

Use `shard tokens scopes` to list available scopes.

The default signing key is created automatically on first use. A custom signing key file must already exist.

The response includes the API key. Use its `token` value as `SHARD_API_KEY`.

Runs only on the daemon host and refuses `--remote`, `SHARD_REMOTE` and a saved connection.

### shard tokens list

List API keys and their status.

```text
shard tokens list [OPTIONS]
```

**Examples**

```sh
shard tokens list
shard tokens list --format json
```

**Options**

| Option | Description | Default |
| --- | --- | --- |
| `--signing-key-file <path>` | locate the token registry beside this key | `<root>/auth/signing-key` |
| `--format <format>` | output format: json or table | `table` |

Table columns: ID, NAME, ISSUED, EXPIRES, SCOPES and STATUS. Does not create a signing key.

Runs only on the daemon host and refuses `--remote`, `SHARD_REMOTE` and a saved connection.

### shard tokens revoke

Revoke an API key.

```text
shard tokens revoke [OPTIONS] TOKEN
shard tokens revoke [OPTIONS] --name NAME
```

**Examples**

```sh
shard tokens revoke 0123456789abcdef
shard tokens revoke --name build-agent
```

**Arguments**

| Argument | Description |
| --- | --- |
| `TOKEN` | token ID from `shard tokens list` |

**Options**

| Option | Description | Default |
| --- | --- | --- |
| `--name <name>` | revoke all tokens with this name |  |
| `--signing-key-file <path>` | locate the token registry beside this key | `<root>/auth/signing-key` |

Revoked tokens are rejected on subsequent requests.

Runs only on the daemon host and refuses `--remote`, `SHARD_REMOTE` and a saved connection.
