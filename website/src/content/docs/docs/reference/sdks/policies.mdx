## shard.policies.set

Store a network policy, or replace all of its rules.

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
shard.policies.set(name: string, rules: PolicyRule[]): Promise<Policy>
```

</TabItem>
<TabItem label="Python">

```python
shard.policies.set(name, rules) -> Policy
```

</TabItem>
</Tabs>

**Examples**

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
await shard.policies.set("api-only", [{ action: "allow", rule: "api.example.com" }]);
await shard.policies.set("ssh-only", [{ action: "allow", rule: "203.0.113.0/24 tcp:22" }]);
```

</TabItem>
<TabItem label="Python">

```python
from useshards import PolicyRule

shard.policies.set("api-only", [PolicyRule("allow", "api.example.com")])
shard.policies.set("ssh-only", [PolicyRule("allow", "203.0.113.0/24 tcp:22")])
```

</TabItem>
</Tabs>

**Arguments**

| Argument | Description |
| --- | --- |
| `name` | policy name; up to 64 lower-case letters, digits and hyphens, starting with a letter or a digit |
| `rules` | `{ action, rule }` in TypeScript, `PolicyRule(action, rule)` in Python; `action` is `allow` or `deny` |

Rules apply in the order given. The first match decides access. Traffic that no rule allows is denied. A sandbox that holds the policy enforces the new rules.

A rule takes the form `shard policy create` uses: a destination with an optional protocol and ports, such as `suffix:example.com tcp:443`. See [Rules](/docs/reference/cli/policies/#shard-policy-create) in the CLI reference.

## shard.policies.get

Return a policy and the sandboxes that use it.

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
shard.policies.get(name: string): Promise<Policy>
```

</TabItem>
<TabItem label="Python">

```python
shard.policies.get(name) -> Policy
```

</TabItem>
</Tabs>

**Examples**

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
const { rules, holders } = await shard.policies.get("api-only");
```

</TabItem>
<TabItem label="Python">

```python
policy = shard.policies.get("api-only")
print(policy.rules, policy.holders)
```

</TabItem>
</Tabs>

A `Policy` holds `name`, `rules`, `holders` (the sandboxes it is attached to) and `dns` (`open` or `closed`, whether the rules let the sandbox resolve names).

## shard.policies.attach

Assign a network policy to a sandbox.

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
shard.policies.attach(sandbox: SandboxRef, name: string): Promise<SandboxInfo>
```

</TabItem>
<TabItem label="Python">

```python
shard.policies.attach(sandbox, name) -> SandboxInfo
```

</TabItem>
</Tabs>

**Examples**

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
await web.stop();
await shard.policies.attach(web, "api-only");
await web.start();
```

</TabItem>
<TabItem label="Python">

```python
web.stop()
shard.policies.attach(web, "api-only")
web.start()
```

</TabItem>
</Tabs>

**Arguments**

| Argument | Description |
| --- | --- |
| `sandbox` | a `Sandbox`, or its ID, ID prefix or name |
| `name` | policy name |

The sandbox must be created or stopped. The policy replaces any policy already assigned to the sandbox. To assign one at create time, pass `policy` to [`shard.create`](/docs/reference/sdks/sandboxes/#shardcreate).

## sandbox.egressLog / egress_log

Return the network decisions the daemon holds for a sandbox, oldest first.

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
sandbox.egressLog(): Promise<EgressDecision[]>
```

</TabItem>
<TabItem label="Python">

```python
sandbox.egress_log() -> list[EgressDecision]
```

</TabItem>
</Tabs>

**Examples**

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
for (const d of await sandbox.egressLog()) console.log(d.verdict, d.host, d.port, d.ruleText);
```

</TabItem>
<TabItem label="Python">

```python
for d in sandbox.egress_log():
    print(d.verdict, d.host, d.port, d.rule_text)
```

</TabItem>
</Tabs>

An `EgressDecision` holds `time`, `source` (`proxy`, `host` or `dns`), `verdict` (`allow` or `deny`), `host`, `port`, `address`, `reason`, the ID of the rule that decided it in `rule` (or why none did, as `default`), and that rule as the CLI spells it (`ruleText`, or `rule_text` in Python).

## sandbox.followEgressLog / follow_egress_log

Stream network decisions as they happen.

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
sandbox.followEgressLog(options?: { signal?: AbortSignal }): AsyncGenerator<EgressDecision>
```

</TabItem>
<TabItem label="Python">

```python
sandbox.follow_egress_log() -> Follow[EgressDecision]
```

</TabItem>
</Tabs>

**Examples**

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
for await (const d of sandbox.followEgressLog()) console.log(d.verdict, d.host);
```

</TabItem>
<TabItem label="Python">

```python
with sandbox.follow_egress_log() as follow:
    for d in follow:
        print(d.verdict, d.host)
```

</TabItem>
</Tabs>

The stream yields the newest decisions the daemon holds, then each new one as it happens, and ends when the sandbox stops. In TypeScript, an abort ends it. In Python, closing it ends it, and `AsyncShard` iterates it with `async for`.

For the whole flow, see [Credential brokering](/docs/essentials/credential-brokering/).
