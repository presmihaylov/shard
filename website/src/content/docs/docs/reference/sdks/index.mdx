Drive sandboxes on a shard server from code. Both SDKs are named `useshards`, have the same methods and talk to `shard serve` on your server.

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```sh
npm install useshards
```

The package needs Node 20.3 or later. It is an ES module, so load it with `import`, and it ships its own type definitions.

</TabItem>
<TabItem label="Python">

```sh
pip install useshards
```

The package needs Python 3.11 or later and ships with type hints. `Shard` is for blocking code and `AsyncShard` is for asyncio. The examples in this reference use `Shard`, and [Asyncio](#asyncio) covers the differences.

</TabItem>
</Tabs>

**Get started**

```sh
export SHARD_REMOTE=https://shard.example.com
export SHARD_API_KEY='your-api-key'
```

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```js title="demo.mjs"
import { Shard } from "useshards";

const shard = new Shard();
try {
  // Create a sandbox.
  const sandbox = await shard.create({ image: "alpine:3.20", name: "demo", memoryMiB: 512 });
  try {
    // Run a command in it. Prints 0 hello.
    const result = await sandbox.exec(["echo", "hello"]);
    console.log(result.exitCode, result.stdout.trim());
  } finally {
    // Remove the sandbox.
    await sandbox.remove({ force: true });
  }
} finally {
  shard.close();
}
```

Run it with `node demo.mjs`.

</TabItem>
<TabItem label="Python">

```python title="demo.py"
from useshards import Shard

with Shard() as shard:
    # Create a sandbox.
    sandbox = shard.create("alpine:3.20", name="demo", memory_mib=512)
    try:
        # Run a command in it. Prints 0 hello.
        result = sandbox.exec(["echo", "hello"])
        print(result.exit_code, result.stdout.strip())
    finally:
        # Remove the sandbox.
        sandbox.remove(force=True)
```

Run it with `python demo.py`.

</TabItem>
</Tabs>

Replace `https://shard.example.com` with your server URL and `your-api-key` with your API key. The script prints `0 hello`. Its `finally` removes the sandbox even when a command fails, because a sandbox outlives the script that made it.

## Environment variables

| Variable | Description |
| --- | --- |
| `SHARD_REMOTE` | URL of `shard serve`, read when the client gets no `remote` |
| `SHARD_API_KEY` | API key, read when the client gets no API key |
| `SHARD_CA_FILE` | PEM file of the CA that signed the server's certificate, read when the client gets no CA file |

The SDKs never read the connection that `shard setup` saves. See [`Shard`](/docs/reference/sdks/client/#shard) for the precedence rules.

## Asyncio

`AsyncShard` takes the same arguments as `Shard`, and with none it reads the same environment variables. Await its request methods:

```python
import asyncio

from useshards import AsyncShard


async def main() -> None:
    async with AsyncShard() as shard:
        # Create a sandbox.
        sandbox = await shard.create("alpine:3.20", memory_mib=512)
        try:
            # Run three commands at once. Prints their outputs in order, 0 to 2.
            results = await asyncio.gather(*(sandbox.exec(f"echo {n}") for n in range(3)))
            print([r.stdout for r in results])
        finally:
            # Remove the sandbox.
            await sandbox.remove(force=True)


asyncio.run(main())
```

Use `async with`, or call `await shard.aclose()` when you are done. Iterate `follow_logs()` and `follow_egress_log()` with `async for`. Cancelling the task ends the wait but not the command.
